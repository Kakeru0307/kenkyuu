# Progress slides (研究進捗)

## Outputs

| File | Role |
|---|---|
| `docs/その他/スライド用/進捗スライド_<短いラベル>.md` | 発表用。1 見出し ≒ 1 スライド |
| `docs/その他/スライド用/次回ミーティングゴール.md` | Goal 一覧の正本（% のみ） |

既存の進捗 md を直す指示なら新規ファイルを増やさない。ラベル例: `リードST5000_GAPS_Drive`。

## Hard rules

- ドキュメントタイトルは **「研究進捗」のみ**（長い副題を付けない）
- 進捗は **% のみ**（完了 = 100%）。文章で「ほぼ完了」などと書かない
- 本線仕様を誤称しない（`.cursor/rules/project.mdc`）
- 技術指標は概念で語る（数式・実装細部はユーザーが求めたときだけ）
- 判断用の一時 py / ワンショット json・md は作らない

## Procedure (fixed order)

### 1. 素材を集める

- この会話の実施内容 + `.cursor/handoff/HANDOFF.md`（Goal / Status / Next）
- 必要なら直前ミーティング PDF / 画像のゴール頁（番号指定があればその頁）
- 数値は実測のみ（MAD など）。未計測は書かないか「未計測」

### 2. 進捗スライド md を書く（前半）

先頭テンプレ:

```markdown
# 研究進捗

> 発表・スライド作成用。1 見出し ≒ 1 スライド。

---

## スライド 1 — 研究進捗

- （この期間の要点 2〜4 行）
```

続きは **話題に応じて** 足す。今回型の定番順:

| # | 見出し例 | 中身 |
|---|---|---|
| 2 | 指標の説明（任意） | 例: MAD とは（低いほどよい・分布距離・1曲点ではない） |
| 3 | 前回/1回目の結果 | 数値 + **何がダメだったか**（参照基準ミス等） |
| 4 | いまの基準線 | 直した条件での数値・以後の比較起点 |
| 5 | いまの生成のダメな点 | 聴感/構造の欠点（伴奏・音域・リード・ばらつき等） |
| 6 | 追加データ / 直したこと | 入れたコーパス・比率・音域・学習方針 |

ユーザーが「5にダメな点、6に追加データ」などと頁を指定したらその番号に従う。  
不要な頁（旧アーキ詳細・長すぎる年表）は入れない。ユーザーが削れと言ったら削る。

### 3. 次回ミーティングゴール.md を同期

1. 前回ゴール（PDF 8–9 枚相当など）があれば **文言を正本に合わせて** 書き直す
2. **やっていない Goal の % は変えない**
3. **進んだ Goal だけ % を更新**（ユーザー指定があればその値を優先）
4. 現行 Goal に無い重要作業があれば追加候補を短く提案 → ユーザーが「それで追加」と言ったら足す
5. 各 Goal は次の形:

```markdown
- Goal-N: <一文>　｜　進捗: N%
  - <補足・完了条件を1行>
```

### 4. ゴールを進捗スライドの後ろへコピー

`次回ミーティングゴール.md` の Goal を進捗 md 末尾へ。PDF と同様に分割可:

- `## スライド N — 次回ミーティングまでのゴール (1〜4)`
- `## スライド N+1 — 次回ミーティングまでのゴール (5〜…)`

先頭に `> 進捗は % のみ（完了 = 100%）。` を1回だけ。Goal 本文は正本と同一にする。

### 5. 返答

- 作った/更新したパスを短く示す
- 追加 Goal 案を出した直後でなければ、長い要約は不要

## Pitfalls

- ゴール正本を更新したのに進捗 md 末尾へコピーし忘れる
- 未実施 Goal の % を勝手に上げる
- 「research progress」「週次報告」などタイトルを英語・別題にする
- MAD/本線と無関係な旧スライド塊をそのまま復活させる
- 進捗 md とゴール md で Goal 文言・% を食い違わせる
