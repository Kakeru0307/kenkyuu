# MAD 評価方針（主／副参照）

更新: 2026-11-24  

根拠論文: Aligning Text-to-Music Evaluation with Human Preferences（arXiv:2503.16669）。  
MAD = MERT 埋め込み上の MAUVE を \(-\ln(\mathrm{MAUVE})\) で報告（**低いほど良い**）。人の好みとの対応は標準 FAD より高い、と同論文。

---

## 0. 一言

**目指す分布は実在のギターバンド音。**  
したがって MAD の**主参照は実録音（非 MIDI→SF）**、  
いまの MIDI→同一 SoundFont→WAV 同士の比較は**副参照（診断・公平比較）**とする。

FAD は副指標のまま（CLAP）。主指標は MAD。

---

## 0.1 数値の読み方・目標

定義: \(\mathrm{MAD} = -\ln(\mathrm{MAUVE})\)。範囲は理論上 **[0, ∞)**（低いほど良い）。

| | 値 |
|---|---|
| 理論最小 | **0**（MAUVE=1、分布完全一致） |
| 理論最大 | **なし（∞）** |
| 論文ヒートマップで「近い」例 | MAD ≈ **2.45**（MusicGen-Large ↔ MusicCaps GT） |
| 論文ヒートマップで「遠い」例 | MAD ≈ **5.3〜5.5** |
| 現実的な天井感 | 公開比較ではだいたい **5〜6 台**が頭。極端でも実装床次第で ~7〜10 |

換算の目安:

| MAUVE | MAD |
|---|---|
| 0.1 | ≈ **2.3** |
| 0.01 | ≈ 4.6 |
| ≈0.004 | ≈ **5.5** |
| 0.001 | ≈ 6.9 |

### 現状とゴール感（2026-11-23）

- 現行の副参照 MAD ≈ **5.5** 前後は、スケール上 **遠い側**（MAUVE ≈ 0.004）。論文の「遠いマス」と同帯  
- ただし論文図は MusicCaps／音響モデル同士。こちらはギターバンド参照＋ MIDI→SF なので、**同じレースの最下位という意味ではない**。「参照にはまだ遠い」は事実  
- **目指す目安: MAUVE 0.1 → MAD ≈ 2.3**（論文の「かなり近い」オーダー）。主 MAD（実録音参照）でも同じ目安を北極星にする  

出典ヒートマップ: From Aesthetics to Human Preferences…（arXiv:2504.21815）Fig.2（MAD）。

## 1. 主参照 — 目標分布（実録音）

| 項目 | 内容 |
|---|---|
| 目的 | 「本当に目指す聴感分布」への距離。開発の北極星・最終判定 |
| 参照 | ギターバンド前景の**実録音 WAV**（目標ジャンルに合わせた選曲） |
| 生成 | 現行パイプライン出力（現状は MIDI→SF→WAV でも可。将来レンダが実録音寄りになればそのまま主 MAD が効く） |
| 読み方 | 数字は音色・ミックス差で悪く出やすい。改善は「目標に近づいたか」 |
| 状態 | **`testMad/ref/wav` に実録音 WAV 配置済み（2015本: FMA1430+MTG585）**。詳細は `MAD参照_実録音セット.md` |

論文の FMA-Pop／MusicCaps は汎用 TTM 用。本線の主参照には使わない（目標ジャンルが違う）。

---

## 2. 副参照 — MIDI→同一 SF→WAV

| 項目 | 内容 |
|---|---|
| 目的 | 音色条件を揃えたうえでの「曲・編成の分布」比較。開発中の感度が高い診断 |
| 参照 | 旧: `testMad/ref/midi`（ギター前景インスト MIDI→同一 SF、101 本）。**実録音 WAV は同ツリーの `ref/wav` に統合済み**（主参照と同居。計算時は dir を明示） |
| 生成 | `testMad/gen`（本線 form 等、同一 SF） |
| 用途 | 対抗 MIDI 系との公平比較、メロ／構成変更の効きの確認 |
| 詳細 | `docs/その他/MAD参照_ギターバンド基準と候補曲.md` / `MAD参照MIDI_採用基準と選曲一覧.md` |

副だから不要、ではない。**主がドメイン差で鈍いときの内訳用**。

## 3. 論文セットとの関係（任意の第三）

横並び・スケール感だけ欲しいとき:

- FMA-Pop または MusicCaps を**第三参照**で MAD を別計算してよい  
- 主結果の表には載せない／載せるなら「ドメイン注記つき付録」  
- MusicCaps は低品質混入が問題視されている（2503.16669）。使うなら注記必須  

---

## 4. 運用

1. 同じ生成セット（おおよそ 100 本）に対し、参照だけ差し替えて MAD を計算する  
2. **主表**: 実録音参照の MAD（＋必要なら FAD）  
3. **副表**: `testMad/ref`（SF 揃え）の MAD／FAD  
4. 1 曲ずつの点数は出ない。集合同士の距離  
5. 実装: `testMad/`（`scripts/compute_mad.py`・`colab_mad.ipynb`）。本番 MAD は Colab GPU 想定  

---

## 5. やらないこと

- 主参照を FMA-Pop／MusicCaps に置き換えて「ギターバンド本線の成功」と主張する  
- 副参照（SF 同士）だけ見て最終到達とみなす  
- 主と副の数字を注記なしに同じ表で混在させる  

---

## 6. 決定メモ（2026-11-23）

- 指標: MAD 主・FAD 副（人の好み対応は MAD 側が強い、という論文方針を維持）  
- 参照の主副を入れ替え: **実録音＝主、MIDI→SF＝副**  
- 理由: 最終目標が実在ギターバンド音の分布であるため。開発の向きも主に合わせる  
- 副を残す理由: 生成が SF のあいだ、主 MAD は音色差フロアが大きい。曲内容の差分は副で見る  
- 数値目標の目安: **MAD ≈ 2.3（MAUVE 0.1）**。現状 ≈5.5 は遠い側  
- 2026-11-24: 主参照の実録音は約1,500曲で確定（5,000曲へ薄めない。歌入り・インストポップは主参照に入れない）。内訳は `MAD参照_実録音セット.md`
