## スライド 1 — タイトル

**研究進捗**

## スライド 2 — 全体のどこに入るか

**目指す流れ**

```
ふわっとした日本語
 → 感情（明るさ・勢い）
 → 曲調（進行・キー・テンポ）
 → 曲の構成（Aメロ・サビなど）
 → ギター演奏（バッキング／リード）
 → 表現の付与（奏法など）
```

| 段階 | 奏法付与との関係 |
|---|---|
| バッキング／リード生成 | **先に**音符を作る |
| 奏法付与（今回） | できた演奏に奏法を載せる |
| 曲の作り直し | **しない** |

→ 「演奏を作り直す」のではなく「あとから付ける」

---

## スライド 3 — 処理の流れ

```
【学習】
 合成した地メロ
   → プログラムで奏法を付けた答えを作る
   → 音の特徴と奏法の対応を約 4500 組
   → 小さな分類モデルを学習
   → 学習済みファイルを保存

【生成時】
 いつもどおり MIDI を生成
   → 各音の前後関係などの特徴を取る
   → 奏法の種類を予測（バッキング／リードで使える種類を分ける）
   → 細かい数値を決めて MIDI に書く
   → 本体を奏法付きに更新（比較用に付与前も残す）
```

---

## スライド 4 — 学習データ

| 項目 | 内容 |
|---|---|
| 規模 | 地メロ 1500 本 × 付け方 3 通り ≒ **4500 組** |
| 地メロ | 合成の短い単音フレーズ（約 4 秒） |
| 答えの作り方 | ルールで奏法を選び、深さなどはその都度ランダムに決める |
| 置き場 | Colab 上で都度作り直す（リポジトリには載せない） |

**注意:** 上手い人間の奏法ではなく、**こちらが付けたルール**を覚えている

---

## スライド 5 — 奏法の種類

| 系統 | 例 |
|---|---|
| なし | 付けない |
| 音の長さ・強さ | スタッカート、ゴースト、パームミュート |
| ピッチベンド系 | ビブラート、チョーキング、プリベンド、アーミング、スライド |
| 音を増やす系 | トレモロ、トリル、ハンマリング、プリング、タップ |

種類が決まったあと、深さ・速さ・音の短さなどを範囲内でランダムに決めて書き込む

---

## スライド 6 — 限界と次にやること

**いまの限界**

- 教師が合成ルールなので、人間らしい付け方にはならない
- 「なし」以外の正答率が約 15% と低い
- 音を増やす系や速い曲では、まだうるさくなりやすい

**次**

1. **リードのフレーズ自体を先に良くする**（旧 pair は不要 → 新定義で再生成・新規学習）  
   → フレーズが弱いと、奏法を付けても効果が出にくい  
   → 方針: [`docs/データ/リードフレーズデータ候補.md`](../../データ/リードフレーズデータ候補.md)
2. 教師を良くする（実演奏への注釈など）→ [`docs/課題/奏法付与改善案.md`](../../課題/奏法付与改善案.md)
3. 深さなどの数値も、ランダムではなく学習で決める

## スライド 7 — 次回ミーティングまでのゴール

| ゴール | 進捗 |
|---|---|
| Whole-song-gen の動作確認と試験生成 | 100% |
| MIDI から音声への変換パイプラインの整備 | 100% |
| DadaGP へのアクセス申請と活用計画の着手 | 0% |
| ギター奏法付与層の実装と生成パイプライン接続 | 100% |
| MIDI への奏法付与を、学習を通じて改善する | 0% |
| リードフレーズ改善のためのデータ再生成・再学習 | 0% |

奏法改善の内訳

- データ: 実演奏への奏法ラベル付け、または合成付け方の見直し
- 学習: 再学習して種類予測を良くする
- 学習: 深さなどの数値もランダムではなく学習で決める
- 確認: 聴感でうるさくないこと

リード改善の内訳

- データ: lead pairs の再生成
- 学習: 新規学習と ckpt 差し替え
- 確認: 生成フレーズの聴感確認
