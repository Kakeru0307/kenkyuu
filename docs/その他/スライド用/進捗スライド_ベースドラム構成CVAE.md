## スライド 3 — 全体の流れ

```
文。例: しんみりとした曲
  → 感情スコア8種。喜び・悲しみ・怒りなど
  → 明るさ・激しさの2軸
  → 曲の色の推定。主題進行・キー・テンポ・勢い
  → 曲の並び
        ・構成テンプレの抽選。雰囲気に応じた重み、または学習モデル
        ・区間ごとのコード進行。主題または対比
        ・区間ごとのドラム型
  → 区間ごとに4つの演奏モデル。伴奏 / リード / ドラム / ベース
  → 1本の MIDI。4トラックと構成メタデータ
```

- キー・テンポは曲全体で固定
- コード進行・ドラム型・区間の長さは区間ごとに変えられる

## スライド 4 — 感情処理の刷新。8スコアから明るさ・激しさへ

**何が問題だったか**

- 感情スコア8種を、楽しい／悲しい／穏やか／緊張の4ラベルに潰していた
- 潰し方が曖昧で、曲の色推定と人間評価の軸がずれやすかった

**何をしたか**

- 各感情を明るさと激しさへ写す対応表で、8スコアを2軸に変換
- 曲の色を決めるモデルの入力を、感情8と明るさ・激しさ2の計10次元に更新
- ラベル分類を挟まず、連続値のまま明るさ／激しさを保持

**ポイント**

- 曲の色推定・曲の並び・評価画面まで、同じ2軸を通す

---

## スライド 5 — 明るさ・激しさの2軸とは何か

**2軸の意味。各軸は -1 から +1**

| 軸 | 一般名 | 見ているもの | 例 |
|---|---|---|---|
| 明るさ | Valence | ポジティブかネガティブか | 喜び寄りなら明るい。悲しみ寄りなら暗い |
| 激しさ | Arousal | エネルギーが高いか低いか | 怒り・驚きなら激しい。悲しみなら静か寄り |

**平面上の位置**

```
          激しさ +
              │
   暗い・激しい │ 明るい・激しい
   怒り・恐れ   │ 喜び・期待
 ───────────────┼─────────────── 明るさ
   暗い・静か   │ 明るい・静か
   悲しみ       │ 信頼など
              │
          激しさ -
```

**どう計算するか**

1. 文から感情スコア8種を得る。喜び・悲しみ・怒りなど  
2. 各感情にあらかじめ置いた明るさ・激しさの座標を用意する  
3. スコアを重みにした加重平均で、明るさと激しさの1点を出す  

例: 悲しみのスコアが高い文は、暗くやや静か側に寄る

**なぜこの2軸か**

- 4ラベルへの分類だと、どちらにも当てはまる中間が潰れる
- 2軸なら連続値のまま扱え、曲の色や構成テンプレの重みに直接使える
- 人間評価でも「明るい／暗い」「激しい／静か」として説明しやすい

**このプロジェクトでの使い先**

| 使い先 | 役割 |
|---|---|
| 曲の色の推定 | 入力の一部。感情8と明るさ・激しさ2 |
| 曲の並び | 構成テンプレの選ばれやすさを調整 |
| 生成メタデータと採点画面 | その曲がどの象限寄りの雰囲気か記録・表示 |

## スライド 6 — ベース追加

**方針**

- ギターと同じ「コード骨格 → 演奏」の流れ
- ベース音域・ベース音色に限定して出力

**実装の役割**

| 役割 | 内容 |
|---|---|
| 教師データ生成 | 勢いに応じたベースライン。キック位置と連動 |
| 学習用ペア作成 | 骨格入力とベース正解の組 |
| 学習 | 既存の伴奏系学習スクリプトを流用 |
| 単体生成 | ベースだけ生成する入口 |
| 曲全体への統合 | 長尺生成で常にベースを含める |

**ポイント**

- ドラムのキックに合わせたルート音を優先
- 区間の勢いを低／中／高で変え、ベースの密度を変える

## スライド 7 — ドラム追加。初版の課題

**初版**

- 勢いの高低だけでキック／スネア／ハットの密度を制御
- 長尺生成に組み込み、4トラック MIDI まで到達

**聴感上の問題**

- 8ビートらしさなど、典型パターンが弱い
- モデルが密度しか見ておらず、ビートの型が条件として渡されていない

→ **ビート型のカタログと、型を条件として渡す** 方向へ改修

---

## スライド 8 — ドラムのビート型カタログ

**設計**

- 12種類のビート骨格を固定し、装飾だけを揺らす
- 演奏モデルへの入力に、どの型かを示す条件チャンネルを追加

**型の例**

| 型の役割 | 聞こえ方 |
|---|---|
| 定番8ビート | 一般的なロック／ポップ寄り |
| 4つ打ち | サビ向けの床キック |
| ハーフタイム | Bメロ／ブリッジ向けの間延び感 |
| バラード疎 | イントロ／アウトロ向けの少なめ |
| 16ビート／ファンク寄り | サビの盛り上げ |
| ダブル系 | 高テンポ寄りの迫力 |

- 型ごとに自然なテンポ帯を教師データで保証
- 旧の勢い密度のみのデータや旧モデル重みとは非互換

---

## スライド 9 — ビート型は曲の並びが選ぶ

**なぜ曲の並び層か**

- 曲の途中でビートが変わるのは、イントロやサビといった区間の役割に依存する
- 勢いだけだと、落ちサビ以外でも激しい型が混ざる

**区間の役割と候補の例**

| 区間の役割 | 候補の例 |
|---|---|
| イントロ / アウトロ | バラード疎、定番8ビート |
| Aメロ | 定番8ビート、16ビート、シャッフル |
| Bメロ / 間奏 | ハーフタイム系 |
| サビ | 4つ打ち、16ビート／ファンク、ダブル系など |

- 役割ごとの候補表から重み付きで抽選
- 長尺生成の入口で、区間ごとにドラム条件を切り替え

## スライド 10 — 曲の並び改善。ループ感の解消

**問題**

- 構成テンプレはあるが、コード進行・テンポ・キーが曲全体で固定
- 同じ進行の繰り返しに聞こえやすい

**改善。まずルールで**

| 項目 | 方針 |
|---|---|
| 主題進行 | 曲の色推定が決める家の進行 |
| 区間進行 | イントロ／A／アウトロは主題。B／間奏／サビは同調性の対比進行 |
| 区間の長さ | 役割ごとに決める。現状サビも8小節 |
| 評価用データ | 生成 MIDI と一緒に構成メタデータを保存し、採点画面で確認 |

**呼び出しの約束**

- 主題進行・調性は必須。曖昧な省略はエラー
- 明るさ・激しさも渡し、テンプレ抽選の重みに使う

## スライド 11 — 構成テンプレの拡張と学習

**テンプレ**

- 既存: 短い曲 / 標準 / 長め
- 追加: バラード寄り / サビ繰り返し / 落ちサビ寄り / 長尺＋間奏

**いますぐ効く段階。ルール**

- 明るさ・激しさでテンプレの選ばれやすさを調整
  - 暗く静か → バラード寄りを強化
  - 激しさが高い → サビ繰り返し／落ちサビ寄りを強化

**あとから学習する段階**

| 役割 | 内容 |
|---|---|
| モデル定義 | 明るさ・激しさ・テンポからテンプレを選択 |
| 教師データ生成 | 上記ルールから正解ラベルを大量作成 |
| 学習 | 分類損失で小さなネットワークを学習 |
| 学習済み重み | あれば自動で使い、無ければルールに戻る |

## スライド 12 — 毎回同じ演奏になる問題と確率的生成

**問題**

- 通常の演奏モデルは、同じ入力なら常に同じ出力
- 同じ進行・同じ条件の区間は、全く同じ演奏になる
- 乱数シードは上流の抽選用で、演奏そのものの多様化にはならない

**根本改善: 条件付きの確率的生成**

```
学習時: 正解演奏を見て潜在変数を推定 → 骨格と潜在変数から再構成
推論時: 標準正規から潜在変数を引く → 同じ骨格でも演奏が変わる
```

- 伴奏・リード・ベース・ドラムすべてで、入力と出力のチャンネル数が違う構成に対応

## スライド 13 — 確率的生成を入れるときに直した穴

| # | 問題 | 修正 |
|---|---|---|
| 1 | 入力と出力のチャンネル数が同じ前提で学習が落ちる | 入力と出力のチャンネルを別々に持つ |
| 2 | 学習済み重みに誤った入力チャンネルが保存される | 実際のチャンネル数を保存 |
| 3 | 読み込み時にチャンネルを復元しない | 重みから復元してモデルを組む |
| 4 | 確率的生成時にテンポや衝突防止条件を付け忘れる | モデルが要求する入力数を見て付与 |

- ドラムも確率的学習・推論に対応
- Colab で4モデルを再学習し、学習済み重みを差し替えれば有効化

## スライド 14 — 曲の色と構成テンプレの2つの推定

| 推定の役割 | 入力 | 出力 | 置き場 |

| 曲の色の推定 | 感情スコアと明るさ・激しさ | 主題進行・キー・テンポ・勢い | `checkpoints/structure_prior/` |
| 構成テンプレの推定 | 明るさ・激しさとテンポ | テンプレの選択確率 | `checkpoints/template_prior/` |

**整理作業**
