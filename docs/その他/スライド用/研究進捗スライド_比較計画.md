# スライド 2

## 比較する相手の研究

### M⁶ GPT³　　Pocwiardowski et al., 2024

- 英語の自由文からマルチトラックの MIDI を生成する
- 内部で明るさと激しさの数値も使っている
- 雰囲気の一致・音楽品質・分布の近さをすべての軸で比べる

### Whole-song-gen　　Wang et al., 2024

- 最大256小節の曲を生成できる
- 文の入力には対応しておらず、ポップ系の曲で学習している
- 音楽品質と分布の近さの2軸で比べる
- スタイルの違いは論文中に明記する

# スライド 3

## 自動評価の方法　FAD と MAD

自動で計算できる指標を2種類使う。どちらも生成した曲が人の演奏に近いかどうかを数値で表す。

### FAD　フレシェ音声距離

- 生成した曲を音楽と言葉の両方で学習した数値変換モデルに通す
- 数百曲分の数値をまとめた分布と、参照の分布との距離を計算する
- 小さいほど参照に近い

### MAD　マウブ音声発散

- 生成した曲を音楽専用の自己学習モデルに通す
- 分布の距離を言語モデルの評価手法を転用して計算する
- 小さいほど参照に近い
- FAD より人の好みとの対応が高い研究結果がある

# スライド 4

## 自動評価の計算手順

1. 同じ日本語のプロンプトを、この研究と M⁶GPT³ に渡して MIDI を生成する。Whole-song-gen はテキスト入力がないためランダム生成で同数の曲を用意する
2. 全パートを同じ仮想楽器音源でミックスして音声ファイルに書き出す
3. 参照として、人が作ったロック・メタル系の MIDI を同じ音源で書き出す
4. 生成した音声と参照の音声をそれぞれ数値に変換する
5. 分布の距離を計算する

注意点

- 比較は1曲ずつではなく、100曲以上をまとめて行う
- 全システムを同じ仮想楽器音源で鳴らすことで条件を揃える

# スライド 5

## 人が聴く評価の方法

### 手順

1. この研究と比較相手の音声を評価者に聴かせる
2. 日本語のプロンプトを提示した上で各軸を1から5で評定させる
3. 評価者1人あたり複数の組み合わせを聴かせ、順序はランダムにする
4. どちらがこの研究の生成物かは隠す

### 評価軸

| 軸 | 内容 |
|---|---|
| 旋律の豊かさ | 旋律として音楽的・調和的に聞こえるか |
| リズムのまとまり | 拍・リズムにまとまりがあるか |
| 構造のまとまり | 反復や展開など、構成的なまとまりがあるか |
| 技術的な完成度 | 突然の無音や不自然な飛びが少ないか |
| 総合満足度 | 総合的な聴感品質への満足度 |
| 雰囲気の一致 | 日本語の雰囲気に合っているか。M⁶GPT³ との比較のみ |
| 明暗・激しさの一致 | 評価者が感じた明るさと激しさが狙いの方向に入ったか。M⁶GPT³ との比較のみ |

# スライド 6

## 比較の対応関係

| 評価軸 | この研究 | M⁶ GPT³ | Whole-song-gen |
|---|---|---|---|
| 旋律・リズム・構造・完成度・総合 | ✓ | ✓ | ✓ |
| 雰囲気の一致 | ✓ | ✓ | 文の入力なし |
| 明暗・激しさの一致 | ✓ | ✓ | 文の入力なし |
| FAD・MAD | ✓ | ✓ | ✓ |

M⁶GPT³ との入力条件の違い

- M⁶GPT³ は英語で詳細な構造まで書いた条件で動く
- この研究は日本語の雰囲気文だけで動く
- 入力条件の差は論文中に明記した上で比較する

# スライド 7

## 主張と今後の課題

主張

- 音楽用語のない日本語の雰囲気文だけで、狙いの雰囲気に合った数分の MIDI を出せる
- 旋律・リズム・構造・完成度・総合の5軸で、比較相手と同等以上を目指す
- 雰囲気の一致と明暗・激しさの方向一致で、M⁶GPT³ より高い評定を目指す

今後の課題

- 数分の曲を安定して出力できるようにする
- 100曲以上の生成を揃えて FAD・MAD を計算する
- 評価者を集めて人が聴く評価を実施する
