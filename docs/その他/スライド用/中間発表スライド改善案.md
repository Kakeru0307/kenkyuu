# 中間発表スライド改善案

> 対象: `中間発表スライド.pdf`（2026-08-20 想定）  
> 根拠: 発表フィードバック3点  
> 方針: 枚数を大幅に増やさず、**不足している説明を1〜2枚で補う**／既存スライドは文言差し替え中心  
> データ・感情・評価の詳細: [`中間発表_データと基準.md`](./中間発表_データと基準.md)

## フィードバックと対応方針

| # | 指摘 | 現状PDFの弱点 | 対応 |
|---|---|---|---|
| 1 | ツール（ソフト・AIモデル）やデータ（量・種類）が不明 | 技術名が散在し、一覧がない | **新スライド「使用技術とデータ」**を追加 |
| 2 | タイトルに「感情」があるが本文が薄い。感情のモデル化が不明 | 「明るさ・激しさ」だけで止まり、WRIME→条件化の説明がない | **全体の流れを感情付きで書き換え**＋必要なら感情専用の短い1枚 |
| 3 | 分かりやすいデモが必要（時間制約のため画面キャプチャ推奨） | 生成例は文字のみ | **到達点スライドにデモ手順を明記**＋録画台本を用意 |

## 推奨スライド構成（差し替え後）

**置き場所の決め方:** 02–05は「なぜこの研究か」。感情の中身とデータ／モデルは、流れ図の **直後** に2枚続けて置く。流れ図だけだと「明るさ・激しさ」で止まり、データだけ先に出すとタイトルの「感情」がまた薄くなる。

04と05の重複は畳んで枚数を出す（位置づけ＋目的を1枚でも可）。

| 番号 | 見出し | 変更 |
|---|---|---|
| 01 | タイトル | そのまま |
| 02 | 分野と問題 | DAW下書きはここだけ |
| 03 | 既存で解けていること | そのまま |
| 04 | 位置づけ＋目的 | 04と05を畳む。感情条件は「導入するもの」1行だけ |
| **05（旧06）** | **全体の流れ** | 感情が **どこに入るか** だけ示す（変換の中身は次へ） |
| **06（新）** | **感情をどう模型化するか** | フィードバック2の本体 |
| **07（新）** | **使用モデルとデータ** | フィードバック1の本体（内部の件数・種類） |
| 08（旧07） | 曲の色・並びと役割 | 表のみ。設計メモは削除 |
| 09（旧08） | 到達点＋デモ | デモ方針 |
| 10–12 | 評価・スケジュール・結論 | 結論は3行。感情の説明は06に任せる |

並べ方: **流れ（地図）→ 感情（変換）→ データとモデル（何で学習したか）→ 構成と到達点**。

詳細の正本は [`中間発表_データと基準.md`](./中間発表_データと基準.md)。スライドは表と1図に限る。

## スライド改訂原稿

### スライド 04（旧04+05を畳む）— 位置づけと目的

- 狙い: ピアノ等でできた文→MIDIを、ギターバンドの役割制約つきへ移す
- 導入するもの（各1行）: 感情条件／曲の並び／4パートMIDI
- 感情の変換手順は書かない（06へ）

### スライド 05（旧06）— 全体の流れ（地図だけ）

**見出し**: 全体の流れ｜感情は上流の条件

図は箱を大きくする。変換の中身は載せない。

```text
雰囲気文
  → 8感情の強さ
  → 明るさ・激しさ
  → 曲の色（進行・キー・テンポ）
  → 曲の並び（区間・ドラムのリズム型）
  → 4パート MIDI
```

下段1行: 感情は演奏を直接書かない。**次の2枚で、変換の中身と、何のモデル／データかを示す。**

### スライド 06（新）— 感情をどう模型化するか

**見出し**: 感情の模型化｜クラス分けしない

**左: 手順**

```text
雰囲気文
  → 日本語感情分析 WRIME（8つの強さ）
  → 各感情を「明るさ・激しさ」平面の決まった位置へ
  → 強さで平均して、明るさと激しさ（連続値）にする
  → 曲条件モデルが進行・キー・テンポを選ぶ
```

**右: 聴衆への約束**

- 分類器（喜び／悲しみ／落ち着き／緊張）は使わない
- 8感情: 喜び・悲しみ・期待・驚き・怒り・恐れ・嫌悪・信頼
- 明るさ＝快／暗さ、激しさ＝高ぶり／穏やかさ（Valence / Arousal）
- 座標は学習しない固定値。強さの重みだけ文から来る
- 例: 「しんみり」→ 悲しみが強い → 暗く穏やか → 遅めのテンポが出やすい
- サビの位置やドラム型は **このスライドの外**（曲の構成）

**口頭（30秒）**

> タイトルの感情はここです。文を8感情の強さで読み、明るさと激しさの2軸に直します。その2軸が曲の色を引きます。メロディそのものは、このあとパート別のモデルが書きます。

### スライド 07（新）— 使用モデルとデータ

**見出し**: 何のモデルで、何を学習したか

内部のチャネル数は出さない。件数は [`中間発表_データと基準.md`](./中間発表_データと基準.md) に合わせる。

#### 使用モデル

| 役割 | 何を使うか |
|---|---|
| 文の感情 | WRIME（公開の日本語感情モデル） |
| 曲の色 | 曲条件モデル（明るさ・激しさから進行・キー・テンポ） |
| 演奏 | パート別 U-Net（伴奏／主旋律／ベース／ドラム） |
| 評価 | MusPy（自動）と聴取 |

#### データ（内部の規模）

| 対象 | 中身 | 規模 |
|---|---|---|
| 伴奏・主旋律 | 規則で作った進行付き MIDI（骨格→演奏） | 伴奏は目標1.5万、いまの定義は2000／主旋律ペア予定6000 |
| ベース | ルートの単音ライン | 既定2000 |
| ドラム | キック／スネア位置が固定のリズム型 | 既定7200（12型） |
| 曲条件 | 人手で採用した文と曲条件の組 | 約145（試作） |
| 実楽曲 | 使わない（主軸は自作の練習用MIDI） | — |

下段1行: 市販の完成音声ではなく、編集できるMIDIをこのデータで学習している。

**口頭（20秒）**

> 感情はWRIME、曲の色は小さな条件モデル、音はパート別U-Netです。教師は市販曲ではなく、進行を付けて作った練習用MIDIです。

### スライド 08（旧07）— 曲の色・並びと役割

表のみ（曲の色／曲の並び）。感情の再解説はしない。06を指すなら「明るさ・激しさが曲の色を駆動」の1行まで。

---

### スライド 09（旧08）— 実装の到達点とデモ

**見出し**: 実装の到達点｜デモ方針

#### 左: 到達表（既存を整理）

| 項目 | 状態 |
|---|---|
| 文 → 感情 → 曲の色・並び → 4パート | 実装済み |
| 各パートの学習 | 再学習・改善中 |
| ギター役割制約 | 反映済み |
| 簡単な画面 | 未着手 |
| ギター下書き評価 | 未実施 |

#### 右: デモ（録画）

**題材文**: 「しんみりとした曲」

**見せること（30〜45秒）**

1. 文を入力（またはコマンドに渡す）
2. ログ／画面で **感情 → BPM・キー・構成** が見える
3. DAW またはピアノロールで **4パート再生**
4. トラックが分かれており **編集可能な MIDI** であること

**制約の見せ場（1つでよい）**

- 伴奏とリードが同じタイミングでぶつかりにくい
- ベースがキックに寄り添う

**本番運用**

- ライブ実行はしない（失敗・待ち時間リスク）
- **事前の画面キャプチャ動画**を本線にする
- バックアップ: 生成済み MIDI を開いて再生のみ

## デモ録画台本（画面キャプチャ）

| 秒 | 画面 | ナレーション案 |
|---|---|---|
| 0–5 | タイトル or 文を大きく表示 | 「雰囲気文からバンド用MIDIを出します」 |
| 5–15 | ターミナル／スクリプト実行。感情・BPM・キーがログに出る | 「まず感情を読み、曲の色を決めます」 |
| 15–35 | DAW／ピアノロールで再生（4トラック見える） | 「伴奏・リード・ベース・ドラムの4パートです」 |
| 35–45 | トラック一覧 or MIDIファイル | 「音声ではなく、編集できるMIDIです」 |

録画のコツ:

- 解像度は発表投影を想定して大きめのフォント
- 音声は生成MIDIだけでよい（BGM不要）
- 失敗時用に、同じ文から出した MIDI を別テイクで用意

## 結論スライド（11）への一言追記

既存の「現状」に次を足す。

- **感情**: 文 → WRIME → 明るさ・激しさ → 曲の色、まで接続済み
- **残課題**: 学習改善・聴取評価・簡単画面・デモの完成度

## やらないこと（スライド肥大化防止）

- 損失関数・チャネル数（12ch / 24ch）の詳細表は質疑用に回す
- ViTex / D3PM の長い説明は入れない（最終形の後段、とだけ）
- 既存研究比較表の行を増やしすぎない（技術・データ新スライドで十分）

## 現行PDF（01–11）の不要・重複の精査

対象は発表に使う `中間発表スライド.pdf`。長く残っている [`進捗スライド_ギター構成評価.md`](./進捗スライド_ギター構成評価.md) は別メモであり、中間発表の原稿ではない（後述）。

### 残す（本線）

| 枚 | 役割 |
|---|---|
| 01 タイトル | 感情条件付き、4パート、という約束 |
| 02 分野と問題 | DAW用MIDI・ピアノ中心の穴、を最初に1回だけ |
| 03 既存で解けていること | 比較表。位置づけの根拠 |
| 06 全体の流れ | 感情を太くして残す（いまは「明るさ・激しさ」だけで薄い） |
| 07 曲の色・並び | 構成が演奏モデルの外であること |
| 08 到達点 | デモ方針を足す。4パート実装済みに更新 |
| 09 評価 | 自動＋聴取を **1枚のまま**（定義文だけで足りる） |
| 10 スケジュール | 残す |
| 12 出典 | 質疑用に残す |

### 削る・畳む（PDF内の重複）

同じ主張が何度も出ている。口頭で拾えるのでスライドからは落とす。

| いまある場所 | 内容 | 判断 |
|---|---|---|
| 02・04・05・11 | 「DAWで直せるMIDIを下書きに」 | **02だけ残す**。04・05・11から削除 |
| 02・04・05・11 | 「ピアノの生成ラインをギターバンドへ」 | **04だけ残す**（位置づけの核）。02は問題の穴、05は導入物に集中 |
| 03 と 04「既存とのずれ」 | 表の繰り返し | 04は「加える役割制約」だけ残し、既存とのずれは03に任せる |
| 05 と 06 | 途中層・4パート・画面 | 05は目的を短く。流れの図は06へ |
| 06 と 07「設計メモ」 | 8小節単位、長い曲は並びで接続 | **07の設計メモを削る**（06の図で足りる）。07は表（曲の色／並び）だけ |
| 08「生成例」と 11 | 「しんみり」→4パート | 生成例は08＋デモ動画。11では繰り返さない |
| 09 | 英語指標名と日本語定義の二重 | **日本語定義＋出典1行**に圧縮。英語IDは質疑 |
| 11 結論 | 出発点／問い／現状が02–08の再掲 | **3行に削る**: 感情で曲の色を決める／4パートMIDIは実装済み／次は学習改善・聴取・画面 |

### 足りない（削る代わりに足す）

詳細は [`中間発表_データと基準.md`](./中間発表_データと基準.md)。スライドには要約だけ。

- ツールとデータ量の1枚（または06の下段）
- 感情: 8感情 → 明るさ・激しさ（クラス分類ではない）
- 伴奏はルートと5度の2音が中心、ドラムはキック／スネアの置き方が型、と一口
- デモは録画（08）

### スライドに載せない（質疑へ）

- 入出力のチャネル数、損失、学習率
- ドラム12型の全表（発表は8ビート／4つ打ち／ハーフタイム程度）
- ViTex の長い説明
- 指標の数式（1軸1枚にしない）

## [`進捗スライド_ギター構成評価.md`](./進捗スライド_ギター構成評価.md) について

中間発表PDFの元ネタだが、**現行実装と食い違う**。発表原稿としては使わない。

| 箇所 | 問題 |
|---|---|
| 全体21枚 | 中間の11枚に対して長すぎる。指標を1軸1枚にしている |

| スライド21 | 「ベース・ドラムが次」「8ラベル再学習」→ どちらも現状と不一致 |

残すなら、到達点と今後だけを [`中間発表_データと基準.md`](./中間発表_データと基準.md) に合わせて直す。中間発表当日の投影はPDF側を正とする。
