## 0. この文書の位置づけ

中間発表で「何のツールとデータを使い、感情をどう模型化し、何を評価するか」を一箇所で示す。

- 自動指標は「壊れていないか」の確認であり、「良い音楽か」の定義には使わない
- 件数は **目標 / いまのテスト設定 / 再生成・再学習待ち** を混同しない

---

## 1. データの流れ

```text
雰囲気文
  → 日本語感情分析 WRIME（8感情の強さ）
  → 明るさ・激しさ（Valence / Arousal）
  → 曲条件モデル（進行・キー・テンポ・主題の進行）
  → 曲の構成（並び・区間の進行・ドラムのリズム型）
  → 伴奏 → 主旋律 → ドラム → ベース
  → 編集可能な4パート MIDI
  → 自動指標（MusPy）／聴取
```

感情はメロディを直接書かない。**曲の色と構成を選ぶ上流の条件**である。  
利用者は進行・キー・テンポを指定しない。

---

## 2. 使用ツール・モデル

| 区分 | 内容 |
|---|---|
| 感情解析 | 日本語感情分析 **WRIME**（公開モデル。文から8感情の強さ） |
| 感情の変換 | 8感情を快・覚醒平面の固定点で加重平均し、**明るさ・激しさ**にする。分類器は使わない |
| 曲条件 | **曲条件モデル**（人手で採用した文と曲条件の組で学習。進行・キー・テンポを出す） |
| 演奏 | パート別 **U-Net**（伴奏／主旋律／ベース／ドラム） |
| 実装 | Python / PyTorch。学習は Colab。生成の入口は現状コマンド（将来は簡単な画面） |
| 評価 | 自動: **MusPy**／聴取: Chu et al. の軸 |

**使わないもの**

- 完成音声を出す市販サービス（本線の生成器ではない）
- ピアノ中心の公開コーパス（主軸にしない）
- 喜び／悲しみ／落ち着き／緊張の4クラス分類（廃止）
- 符号から曲を作り直す経路（注釈は後段、生成の置き換えではない）

## 3. 感情の模型化

雰囲気文を WRIME で読み、次の8感情の強さを出す。

喜び / 悲しみ / 期待 / 驚き / 怒り / 恐れ / 嫌悪 / 信頼

各感情を **明るさ（快）・激しさ（覚醒）** 平面上の固定点に置く（Plutchik の8感情を Russell 平面へ置いた近似。この座標は学習しない）。強さで加重平均し、明るさと激しさ（各 -1〜+1）を得る。

例:

- 喜びが強い → 明るく、やや激しい
- 悲しみが強い → 暗く、穏やか
- 怒りが強い → 暗く、激しい

曲条件モデルの入力は **8感情 + 明るさ + 激しさ**。出力は進行・キー・テンポなど「曲の色」。  
Aメロやサビの位置、ドラムのリズム型は **曲の構成** が決める（感情モデルの仕事ではない）。

廃止: 喜び／悲しみ／落ち着き／緊張への分類器。旧方式の学習済みモデルは使えない。

## 4. 各パートが実際に鳴らしているもの

### 伴奏ギター

- 入力は、小節の頭にコードの構成音だけ置いた骨格。モデルがストローク演奏を埋める
- 1小節を4拍とし、**8回、拍を均等に弾く**（八分音符相当）
- 弾き始めの **約7割** は **ルートと完全5度の2音だけ**（3度が無いので長調／短調がはっきりしない。ロックのギターによくある形。例: ドならドとソ）
- 残る約3割は **3度などを含む通常のコード**
- テンポの学習範囲は 60–150

### 主旋律ギター

- 基本は **1音ずつのメロディ**（短いモチーフの反復と変奏）
- フレーズの一部でルートと5度の2音を置けるが、**伴奏が同じ2音を弾いた瞬間には重ねない**

### ベース

- **コードのルートを単音**で弾く（低い音域）
- ドラムのキックが鳴った位置にルートを寄せる
- 音の密度は区間の盛り上がり（疎／中／密）で変える

### ドラム

1小節＝4拍。キックとスネアの位置はリズム型ごとに固定。ハイハットと装飾だけ確率で揺れる。  
曲の構成が区間の役割に応じて型を選ぶ（学習で型を選ぶのは将来）。

| 呼び方 | 1小節で何が鳴るか | 主な使いどころ |
|---|---|---|
| 基本の8ビート | キック＝1拍目と3拍目、スネア＝2と4、ハイハット＝八分 | Aメロ |
| 4つ打ち | キック＝4拍すべて、スネア＝2と4、ハイハット＝八分 | サビ |
| 16ビート | キック／スネアは8ビートと同じ、ハイハットだけ16分 | Aメロ |
| ファンク寄り16ビート | キックが裏に入り、スネアに小さい音が混ざる | サビ |
| ハーフタイム | キック＝1拍目だけ、スネア＝3拍目 | Bメロ・間奏 |
| ハーフタイム＋シャッフル | 上と同じ骨格、ハイハットが跳ねる | 間奏 |
| バラード（疎） | キック＝1拍目、スネアは細い音で2と4、ハイハットは四分 | イントロ／アウトロ |
| シャッフル8ビート | 8ビートのキック／スネア、ハイハットが跳ねる | Aメロ |
| ディスコ | キックは4つ打ち、ハイハットは裏拍を開いて鳴らす | サビ（少なめ） |
| トレシージョ | キックが 3+3+2 系の連打、スネアは2と4 | カタログに含む |
| レゲエ | キックとスネアが3拍目に寄る | カタログに含む |
| 連打キック | キックが八分で連続、スネアは2と4、シンバル多め | サビ |

生成順は **伴奏 → 主旋律 → ドラム → ベース**。主旋律は伴奏とぶつかりにくくし、ベースはキックに合わせる。

## 5. 学習・生成データ（種類と量）

種類はいずれも **規則で作った練習用 MIDI** が中心。市販曲のコーパスは主軸にしない。

| 対象 | 何を学習するか | 規模 | 状態 |
|---|---|---|---|
| 伴奏 | 骨格 → ストローク演奏 | 目標 15,000 本。いまの定義はテスト **2,000** | 定義変更あり・再生成待ち |
| 主旋律 | 骨格 → 単音メロディ | 予定 **6,000** ペア | 再生成／再学習待ち |
| ベース | ルート単音のライン | 既定 **2,000** 曲 | スクリプト済み |
| ドラム | リズム型つきのパターン | 既定 **7,200**（12型×約600） | スクリプト済み・**再学習待ち** |
| 曲条件 | 文の感情 → 進行・キー・テンポ | 人手採用 約 **145** 件 | 試作規模 |
| 曲の構成 | 並び・区間進行・リズム型 | 並び3種（短い／標準／拡張） | 規則で選ぶ。学習データは未整備 |

本線外: 実録音ギター 98 曲（追加学習はリズムが崩れるため使わない）、検証用 MIDI 3。ピアノ中心の公開セットは採用しない。

曲の構成の並び:

- 短い: イントロ → Aメロ → サビ → アウトロ
- 標準: イントロ → Aメロ → Bメロ → Aメロ → サビ → アウトロ
- 拡張: イントロ → Aメロ → 間奏 → Bメロ → サビ → Aメロ → アウトロ

キーとテンポは曲通しで固定。区間ごとに主題の進行か対比の進行を置く。

## 6. 評価基準

出典と計算の詳細は [`評価基準まとめ.md`](./評価基準まとめ.md)。

### 自動（技術的妥当性）

Yang & Lerch 2020 / MusPy。美しさの判定には使わない。

| 見るもの | 意味 | 方向 |
|---|---|---|
| 調内の音の割合 | 指定した調の音がどれだけ使われているか | 高いほどよい（1 が理想） |
| 空拍の割合 | 音符が無い拍がどれだけあるか | 低いほどよい（無音過多の検知） |
| 同時に鳴る音の数 | 和音の密度 | 極端な偏りが異常 |
| 調が途中で崩れていないか | 曲全体でどれか一つの調に寄っているか | 高いほどよい |

### 聴取（聴感の本判断）

Chu et al., CIKM 2022。5点（1＝全くそう思わない ～ 5＝非常にそう思う）。

| 軸 | 評価者への定義文 |
|---|---|
| 旋律 | 旋律として音楽的・調和的に聞こえるか |
| リズム | 拍・リズムにまとまりがあるか |
| 構造 | 反復や展開など、構造的なまとまりがあるか |
| 破綻の少なさ | 突然の無音・不自然な飛びなど、技術的破綻が少ないか |
| 総合 | 総合的に、この曲の聴感品質に満足できるか |

使わない軸: 創造性・豊かさ・自然さ・一貫性（Chu の残り）、歌声向けの指標、参照曲との分布比較（参照コーパスを置いていないため）。

運用: 生成のたびに自動指標を先に見る。聴取が低い（2以下）ときだけ、その軸に沿って次の修正を考える。
