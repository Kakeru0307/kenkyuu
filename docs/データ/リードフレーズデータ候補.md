## 本決め（2026-10-19・改訂）

「合成だけ」は採用しない。良い公開データがあるのに切ると、フレーズ品質の上限を自分で下げることになる。

| 役割 | データセット | 決定 |
|---|---|---|
| **本線 A（実メロ・量）** | **SynthTab**（JAMS/MIDI） | **採用**。伴奏っぽい和音トラックも含めてよい（極端なゴミだけ除外） |
| **本線 B（実演奏・コード付き）** | **GuitarSet solo** | **採用**。chord 注釈あり。量は SynthTab を補完 |
| **本線 C（形式・条件の橋渡し）** | **合成 lead pairs**（2026-08-01 定義・13ch） | **採用**。穴埋め・条件整合。単独本線にはしない |
| 旧 Colab `data/pairs/lead` | 旧定義残骸 | **使わない**（破棄可） |
| Guitar-TECHS | 既存 98 | **lead 本線には使わない**（奏法教師へ） |
| DadaGP 生 | — | **使わない**（入手不可）。SynthTab がタブ由来の代理 |
| EGDB / IDMT / Lakh | — | **使わない** |

### 追加の本決め（2026-10-19）

| 項目 | 決定 |
|---|---|
| **学習方式** | **CVAE**（Colab の lead CVAE 経路） |
| **SynthTab のコード** | JAMS にコードネーム注釈は基本ない（弦ごとのノート・一部奏法）。骨格用の進行は **ノート列からのコード推定でいく**（可能。精度は実装時に見る） |
| **GuitarSet のコード** | 付属の instructed/performed chord を使う（推定より優先） |
| **backing が無いときの 13ch（power mask）** | **ゼロでよい**。input 骨格は **進行＋キー（＋BPM）に従う**だけで足りる |
| **混合比率** | **実データ（SynthTab+GuitarSet）8〜9割、合成 1〜2割** |
| SynthTab の切り方（下節） | **伴奏っぽい和音トラックも残してよい**（2026-10-19）。極端なゴミだけ落とす |

学習時の形:

1. target = SynthTab + GuitarSet solo（＋合成フレーズで穴埋め）  
2. input = downbeat 骨格（進行＋キー）＋ BPM ＋ power mask（実データはゼロ可）  
3. 学習 = **CVAE・新規**（旧 ckpt resume なし）

## 0. pair についての方針（確定）

| 対象 | 必要？ | 理由 |
|---|---|---|
| **「骨格 → リード」pair で学習する形式** | **必要** | lead U-Net の教師形式。これ以外の本線はない |
| **旧定義の既存 lead pair ファイル** | **不要** | 2026-08-01 以前の均一8分系など、今の教師定義と食い違うなら品質の足かせ |
| **旧 pair 由来 ckpt の resume** | **不要** | 13ch・新フレーズ定義は **新規学習** |

やること（次の実装フェーズ）:

1. 旧 `data/pairs/lead` は残さなくてよい（捨てる／無視）
2. 現行コード定義（2小節モチーフ・可変音価・息継ぎ・13ch power mask）で **再生成**
3. 旧 12ch ckpt から resume せず学習し、`prttype/checkpoints/lead/` を差し替え

「pair 学習をやめる」ではない。「**腐った既存 pair にこだわらない**」。

## 1. 本線が欲しいデータの形

| 必要 | 理由 |
|---|---|
| 単音〜準単音のメロ線 | target はフレーズリード |
| 進行／キー／BPM が取れる or 推定可能 | input は downbeat 骨格＋BPM（＋power mask） |
| 8小節クリップに切れる | patch 128×128 |
| ロック〜メタル寄りが望ましい | 聴感・FAD 参照方針と整合 |
| 今すぐ入手可能 | **DadaGP 生データは使えない**（申請に返信なし） |

## 2. 候補比較

| 候補 | 入手 | 向き | 判定 |
|---|---|---|---|
| **SynthTab**（JAMS/MIDI） | 公開（大容量・CC BY-NC） | タブ由来メロ大量。DadaGP タブ由来だが **別配布なので使える** | **本線 A（実メロ）** |
| **GuitarSet** solo | 公開 | コード注釈あり。acoustic・短尺・スタイル混在 | **本線 B（実演奏＋骨格）** |
| **合成 lead pairs**（`generate_lead_pairs.py`） | 自前 | 13ch・進行整合・量の穴埋め | **本線 C（橋渡し）。単独本線ではない** |
| **Guitar-TECHS**（既存 98） | 済 | エレキ・奏法付き。lead 量不足 | lead 本線向きではない。**奏法教師向き** |
| EGDB / IDMT-SMT-Guitar | 公開系 | 転写ベンチ中心 | lead 生成教師としては不向き |
| Lakh 等汎用 MIDI | 公開 | program 抽出は可能 | 品質・役割分離が荒い保険 |
| **DadaGP 生** | 不可 | GuitarPro 大量 | **ブロック中**。SynthTab を代理経路とする |

## 3. 本決めとの対応

冒頭の **本決め（改訂）** が正。SynthTab / GuitarSet は「将来枠」ではなく **lead 学習に入れる**。

目標の上限: **今よりリードらしいフレーズ**（人間ソロ水準は一気には狙わないが、実メロを捨てて上限を下げない）。

### SynthTab「切り方」とは

学習に入れる／入れないの選別。**伴奏っぽいものも入れてよい**（ユーザー決定）。

| 切り口 | やること |
|---|---|
| 役割 | **和音伴奏も残す**。単音メロだけに絞らない |
| 長さ | 8小節に切れない／短すぎるなど、形式で困るものだけ落とす |
| 密度 | 無音に近い・明らかな破損だけ落とす（厳しすぎる密度カットはしない） |
| （任意）ジャンル | ロック寄りだけ、などは任意 |

閾値の数字は実装時。方針は「広く入れて、壊れたクリップだけ除外」。

障壁（実装時）:

- SynthTab: 上記の切り方、骨格のコード推定、CC BY-NC  
- GuitarSet: acoustic・短い・量少  
- 合成: **全体の 1〜2 割**に抑える（実 8〜9 割）

| 目標 | 現実性 |
|---|---|
| 実メロ（SynthTab/GuitarSet）でフレーズの天井を上げる | 中〜高（取り込みが本体作業） |
| 合成で 13ch・進行条件を安定させる | 高 |
| 上手いギタリスト水準まで一気に | 低 |

## 5. 次に実装するときの手順イメージ（コードは書かない）

1. SynthTab JAMS/MIDI と GuitarSet solo を取得し、8小節・単音度などでフィルタ  
2. 進行（注釈 or 推定）から input 骨格＋BPM を作り、target メロと pair 化  
3. 合成 pair は同形式で追加（比率は実験で決める。初期案: 実 ≥ 合成）  
4. 混合で新規学習 → ckpt 差し替え → 聴感確認
