# ベース・ドラム追加計画

> 最終更新: 2026-08-06（ドラム型カタログ / 構成レイヤ beat_type）

## 方針

ギター（backing/lead）と同型の経路でベースとドラムを追加する。

```
文 → prior → generate_form
               ├─ Backing U-Net   (既存)
               ├─ Lead U-Net      (既存)
               ├─ Bass U-Net
               └─ Drum U-Net（beat_type 条件）
                       ↓
               4トラック MIDI → ViTex注釈（後段）
```

- **ViTex**: 生成後の注釈（コード／hyperscore）。全パート対象。D3PM は使わない
- **モデル分離**: backing/lead と同様に Bass と Drum を別 U-Net とする
- **常時生成**: bass/drum は常に生成。checkpoint 不在時は FileNotFoundError
- **協調**: drum → bass の順で生成し、kick times を bass に渡す

---

## 表現まわり

| パート | MIDI | パッチ |
|---|---|---|
| Bass | program=33（GM Bass, category 4） | tonal 11ch の category 4 |
| Drum | `is_drum=True` | drum (1,128,128) 二値 0/1 |

## ドラム型カタログ（2026-08-06）

### 問題

旧 `makeData/drum.py` は energy=low/mid/high の**密度差だけ**で教師を作っていた。学習で型が混ざり、推論時も beat_type 条件が無いため典型 8 ビート等が崩れた。

### 設計

1. **12 型の骨格固定カタログ**（kick/snare は型ごとに固定。装飾のみ確率変動）
2. **U-Net 条件**: tonal11 + BPM1 + beat one-hot12 = **in_channels=24**
3. **構成レイヤで型を選ぶ**: `FormSection.beat_type` + `ROLE_BEAT_CANDIDATES`
4. energy は guitar/bass の `onset_th`（`ENERGY_DECODE_PARAMS`）にのみ使用

```
ROLE_BEAT_CANDIDATES[role] → sample → FormSection.beat_type
                                     → generate_drum_music(beat_type=...)
```

`halftime` は bridge/b 向け、`four_floor`/`metal_double` はサビ向け、intro/outro はバラード系に限定。energy 連動だと intro(low) に halftime が混ざる問題を避けられる。

### 将来拡張（構成レイヤ学習）

`FormSection.beat_type` はただのフィールドなので、誰が値を入れるかを差し替え可能。

- **現在**: `ROLE_BEAT_CANDIDATES` の静的重み付き抽選
- **将来**: `structure_prior` に beat_type 12 クラス頭を追加し、WRIME+V/A から学習選択。静的テーブルは初期ポリシー／フォールバック

`generate_form.py` は `section.beat_type` を読むだけなので、学習化しても呼び出し側はほぼ無変更。

### 12 型一覧

| id | kick（固定） | snare（固定） | hat |
|---|---|---|---|
| `eight_basic` | 0, 8 | 4, 12 | 8分 |
| `four_floor` | 0,4,8,12 | 4, 12 | 8分 |
| `sixteen_basic` | 0, 8 | 4, 12 | 16分 |
| `sixteen_funk` | 0,3,8,10 | 4,12 + ghost | 16分 |
| `halftime` | 0 | **8** | 8分 |
| `halftime_shuffle` | 0 | **8** | shuffle (0+3) |
| `ballad_sparse` | 0 | 4,12 (side) | 4分 |
| `shuffle_eight` | 0, 8 | 4, 12 | shuffle (0+3) |
| `disco` | 0,4,8,12 | 4, 12 | 裏打ち OH |
| `tresillo` | 0,3,6,8,11,14 | 4, 12 | 8分 |
| `reggae` | **8** のみ | 8 (rim) | 4分 |
| `metal_double` | 全8分 | 4, 12 | 8分 + crash |

BPM は型ごとに `BEAT_BPM_RANGE`（例: ballad 60–95、four_floor 110–150）。

### ROLE_BEAT_CANDIDATES（要約）

| role | 主な候補 |
|---|---|
| intro / outro | ballad_sparse, eight_basic |
| a | eight_basic, sixteen_basic, shuffle_eight |
| b | halftime, eight_basic, sixteen_basic |
| bridge | halftime, halftime_shuffle, ballad_sparse |
| chorus | four_floor, sixteen_funk, eight_basic, metal_double, disco |

## 実装状況（2026-08-06）

| Step | 内容 | 状態 |
|---|---|---|
| 1 makeData | `bass.py` / `drum.py`（12型カタログ） | 済 |
| 2 ペア生成 | `generate_*_pairs.py`（drum count=7200 + `*_beat.npy`） | 済 |
| 3 Dataset | `dataset_drum.py` in=24。旧 `*_beat.npy` なしはスキップ | 済 |
| 4 学習 | bass=`train.py`、drum=`train_drum.py`（BCE, in=24） | スクリプト済・**Colab 再学習待ち** |
| 5 推論 | `generate_bass` / `generate_drum(..., beat_type=)` | 済 |
| 6 form | `FormSection.beat_type` → drum に貫通 | 済 |
| 7 Colab | `DRUM_COUNT=7200` / in=24 明記 | 済 |

### 重要: 旧 ckpt 非互換

- 旧 drum U-Net（in=12）は **使えない**
- Colab で `generate_drum_pairs.py --count 7200` → `train_drum.py` を再実行し、ckpt を `prttype/checkpoints/drum/` に配置すること

### Colab での学習手順

```
TRAIN_BASS = True
TRAIN_DRUM = True
```

1. `generate_bass_pairs.py` → `train.py --pairs-dir data/pairs/bass --checkpoint-dir checkpoints/bass`
2. `generate_drum_pairs.py --count 7200` → `train_drum.py --pairs-dir data/pairs/drum --checkpoint-dir checkpoints/drum`（**in=24**）
3. ckpt を `prttype/checkpoints/bass/` と `prttype/checkpoints/drum/` に配置

### ローカルでの教師スモーク（学習なし）

```powershell
cd kenkyuu\prttype
.\.venv\Scripts\python.exe -c "from makeData.drum import generate_drum_pattern; ..."
.\.venv\Scripts\python.exe generate_drum_pairs.py --count 24 --pairs-dir data/pairs/drum_smoke
```

成功基準（教師）:
- `eight_basic`: K on 0+8 / S on 4+12 / H 8分
- `halftime`: S on tick=8
- `reggae`: tick=0 にキックなし
- `shuffle_eight`: hat ticks `0,3,4,7,8,11,12,15`
