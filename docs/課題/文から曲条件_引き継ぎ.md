# 文→曲条件（VA／条件エンコーダ）引き継ぎ

> 作成: **2026-11-23**  
> 目的: 別チャットで「どう進めるか」を考えるための前提整理。実装指示ではない。  
> 関連: [`VA.md`](VA.md)、本線仕様（`.cursor/rules` / `generate_form.py`）

---

## 1. ユーザーが求めていること（この議論の核）

**文（ふわっと日本語）から、「どのような曲を求めているか」が分かるパラメータが欲しい。**

- 現状の VA（valence / arousal の2数）だけでは解像度が足りない
- 欲しいのは「感情2次元」ではなく、**文が指す曲の仕様・条件ベクトル**
- 例として会話に出たギャップ: Mood 的な指弾きメロ、速弾き、アルペジオ感、テンポ感、ギター寄り、などは V/A だけでは表現しきれない

言い換え:

```text
ふわっと日本語
 →「この曲に欲しいもの」を表すパラメータ一式
 → prior / 構成 / 各パートがそれを使える
```

---

## 2. 本線パイプライン上の位置

現状本線（誤称禁止）:

```text
ふわっと日本語（--text。省略時はカタログ乱択）
 → WRIME/VA（実態は analyze_va = VA encoder）
 → structure prior（ckpt 無ければカタログ乱択）: 進行・キー・BPM 等
 → 構成レイヤ（song_form）: セクション、区間ごとの進行 / beat_type / 奏法 / bars
 → 4パート連結（キー・BPMは曲通し）
 → リード奏法 PB
```

- 進行・キー・BPM の**明示指定 CLI は禁止**（文→条件が本線入力）
- つまり「文理解の出口」を豊かにすることが、ユーザー指定を増やさずに曲をコントロールする本線上の自然な拡張

## 4. 既知のギャップ（設計を考えるとき必須）

### 4.1 VA がパート生成まで届いていない（`VA.md` 問題2）

- VA は構成層（`sample_song_form`）までは渡る
- **backing / lead / drum / bass の生成関数には直接渡っていない**
- 演奏の激しさは energy（low/mid/high）経由で、VA と一対一ではない
- **パラメータを増やしても、下流が受け取らなければ無意味**

### 4.2 教師と軸の対応

- 「文 ↔ そのパラメータ」で揃っていない軸は学習できない
- 自作 VA 文禁止の方針と両立させる必要あり（実データ／既存キャプション／タグから取る）

### 4.3 VA 2次元の限界（今回の問題意識）

- prior（進行・キー・BPM）の粗い制御には足りる面がある
- 「どんなフレーズ／奏法／編成感か」までは足りない
- リード側で「Mood みたいな教師 MIDI」を集める話と直交するが、**文からその型を選ぶスイッチ**が無いと同じ問題が残る

## 5. 考えるべき問い（次チャット向け）

実装に入る前に、少なくとも次を決める／仮説を立てる。

1. **出口パラメータは何か**  
   - VA を残すか  
   - `MUSIC_AXES` で足りるか、groove／奏法／リード型など本線の離散条件まで含めるか  
   - 連続スコアか、離散ラベルか、両方か

2. **誰がそれを消費するか**  
   - prior のみ / song_form / 各パート条件 ch / 奏法選択  
   - 「届いていない」問題をどの層から直すか

3. **教師はどう取るか**  
   - 既存の THETA・Jamendo・WRIME 等でどの軸まで教師が埋まるか  
   - 足りない軸（例: 速弾き／指弾きメロ）の教師戦略

4. **本線との整合**  
   - 明示指定 CLI を増やさない  
   - No silent downscope: 暫定を出すなら理由を明示  
   - VA encoder 差し替えと条件エンコーダ追加のどちらを本線にするか

5. **評価**  
   - 文を変えたときパラメータがどう動くか（回帰・分類）  
   - 生成側で聴感／MAD 等に効くか（最終的には下流接続後）

---

## 6. 会話時点の位置づけ（要約一文）

> 欲しいのは「文→感情2数」ではなく「文→求めている曲の条件パラメータ」であり、条件エンコーダはその器として既に構想・コードがある。一方で下流未接続と教師カバレッジがボトルネックなので、次は出口定義・消費先・教師をセットで設計する。

## 8. 同時進行の別件（混同しない）

同日に進めていた **lead フレーズ MIDI 収集**（Mutopia keep、EGSet12、GuitarDuets、Wikimedia）は、教師 MIDI の話であり、本ドキュメントの「文→条件パラメータ」設計とは別レイヤ。  
文から型を選ぶスイッチが無いと、良い教師を足しても「この文のときはこの型」と結びつかない、という接続だけは共有認識として残す。
