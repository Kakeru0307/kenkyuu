# 曲調層

> 最終更新: 2026-10-12

## 役割

文から得た **V/A（−1〜+1）** を受け取り、曲の色として **BPM・キー・モード・進行** を出す。

```text
文 → VA encoder → StructurePriorNet → StructureParams
                 （BPM / key / mode / progression）
                 energy は BPM から後付け
```

- 明示の進行・キー・BPM 指定は本線に置かない（最終形ルール）
- チェックポイント無し・文無しのときだけカタログ乱択へフォールバック

## 現状（実装・学習）

### できていること

| 項目 | 内容 |

## 現状の問題

### 問題1: 前段 VA encoder の A が潰れる（曲調層の入力品質）

- **場所**: `prttype/emotion_va.py`（XLM-RoBERTa VA）
- 「普通」「作業BGM」などでも **A≈−1** に張り付きやすい。V は 0 付近に残ることがある
- 結果、推論が **低Aゾーンに偏り**、高A×速いテイクが文からは出にくい
- **対策候補**: encoder 差し替え／校正、A の再スケール、文→A の別経路（詳細は `docs/課題/VA.md` を更新予定）

### 問題2: 低V高A が「とても速い」まで行かない

- 学習セット上、低V高A の 116件は **120–149 が約85%**、≥150 はほぼ無し
- モデルも平均 ~123 付近に留まりやすい（データどおり）
- **対策**: 低V高A×BPM≥150 の教師を増やすか、帯の定義を見直す

### 問題3: mode と進行の同時性が弱い

- mode と progression は共有 MLP のあと **独立サンプル**
- 例: highV_lowA で mode=major なのに prog=`minor_rock` が出ることがある
- **対策（決定）**: E3（教師正規化）→ C1（mode 条件付き進行ヘッド）。下記「mode↔進行ルール」

### 問題4: 構成層側は別件のまま

- 区間テンプレ・区間長は構成レイヤ（`song_form.py`）の仕事
- `template_prior` は曲調 prior 本線外（Colab からも外した）
- 長尺・サビ位置は短い prior だけでは完成しない

## mode↔進行ルール（実装済み・再学習待ち）

方針: **E3 → C1**。正の表は prior / 構成 / 合成データで共有する。  
コード: `makeData/progressions.py`（プール・E3・β1） / `structure_prior.py`（C1） / `train_structure_prior.py`（E3適用）。  
**旧 ckpt（mode 条件なし prog）はロード拒否** → Colab で再学習が必要。

### 進行プール（両 mode 可を含む）

| 進行群 | major | natural_minor | 備考 |
|---|---|---|---|
| diatonic_major（`marusa` 等） | ○ | × | |
| diatonic_minor（`minor_*`） | × | ○ | |
| borrowed（`rock_*`） | ○ | ○ | **両 mode 化** |
| blues（`blues_12bar_short`） | ○ | ○ | **両 mode 化** |

`rock_*` / `blues_*` は進行名から mode を一意に決めない（両 mode 可）。  
本格短調ロックは `minor_*`（例: `minor_rock`）が本命。borrowed は「暗い曲への借り和音」用。

### 鳴らし方（β1・平行短調・合意）

home mode = `natural_minor` かつ進行が borrowed / blues のとき:

- **ルート形**は今の major 解決のまま（例: key=`A` の `rock_bVII` → A–G–D–A）
- **スケール／主感**は home mode に従う（A minor）
- 度数の短調リマップ（β2）はしない（定番ロックのルートから外れやすい）

major + borrowed/blues は現状どおり。`minor_*` は従来の短調解決のまま。

### E3（教師正規化）

両ラベルがある行だけ:

| 進行群 | 操作 |
|---|---|
| `minor_*` | `mode ← natural_minor`（衝突なら書き換え、落とさない） |
| diatonic_major | `mode ← major` |
| borrowed / blues | **mode はそのまま**（major / minor どちらも合法） |
| mode 欠落 + borrowed/blues | デフォルト `major`（従来カタログの primary） |

ログに「何件書き換えたか」を出す。EMOPIA 等の prog 無し行は対象外。

### C1（モデル）

```text
VA → h → head_mode(h)
         → head_prog(h, mode_onehot)   # 学習は gold mode（E3 後）
推論: mode サンプル → その mode のプールだけが実質出るよう条件付け
     （必要なら推論時もプール外 logit をマスクして保証）
```

- major 条件の prog 分布: diatonic_major ∪ borrowed ∪ blues  
- minor 条件の prog 分布: diatonic_minor ∪ borrowed ∪ blues  

ckpt はアーキ変更のため再学習必須。

### 構成レイヤの追随

`list_progressions_for_mode` も同じ表にする（minor 曲のコントラストに `rock_*` を含める）。  
`ProgressionSpec.mode` は「primary / 合成デフォルト」として残し、許可集合は `modes`（または family 判定）で持つ想定。  
バッキング／リードは home mode を渡し、borrowed は β1 で鳴らす。

## やらない／やめたこと

| 項目 | 理由 |
|---|---|
| BPM の平均回帰（MSE） | 二峰を平均に潰す |
| energy ヘッド学習 | BPM の影武者になりやすい |
| high_bpm 均等水増し | VA 条件なしで速い確率だけ膨らむ |
| VGMIDI/PMEmo/FME **全量**を extras に同時投入 | balanced_116 の揃えを崩す |
| 推論だけの安直マスクで本線扱い | 学習分布が嘘のまま残る（暫定なら可、本線は E3+C1） |
| borrowed の短調度数リマップ（β2） | ルートが定番から外れやすい。β1 を採用 |
